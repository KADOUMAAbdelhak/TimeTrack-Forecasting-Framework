Dear Editors-in-Chief,

We submit the manuscript ``Contextual Input versus Representation Sharing in Multi-Metric Runtime Forecasting: Selective Gains and a Recurring Sharing Cost'' for consideration as a Full Length Article in Future Generation Computer Systems.

Engineers who forecast runtime telemetry for cloud resource management must decide two things: whether a target's forecaster should receive other resources' telemetry, and whether several resource targets should share one model. Prior comparisons usually change both at once. The manuscript separates them with a 2$\times$2 design (independent or shared models, own-resource or all-resource input) and evaluates CPU, throughput, memory and disk-write forecasting on the Bitbrains fastStorage and Rnd traces and three dependent Materna temporal blocks, with TimeTrack as development data. A second, separately frozen part repeats the design for LSTM, DLinear, PatchTST-style and iTransformer-style backbones and adds descriptive mechanism diagnostics. A dedicated validation-strategy section maps each threat (leakage, sample mismatch, selection freedom, capacity, model family, machine sampling, seed variation, scale dominance and implementation error) to the mechanism that addresses it, and a table maps every main claim to its evidence and its limits.

The main findings are that contextual input gives small, selective and model-dependent benefits, whereas representation sharing carries a recurring accuracy cost: for a typical machine the shared model was less accurate in 54 of 56 comparisons across six data blocks and four backbones. We then ask whether this cost can be managed with data that engineers already have. The inner-validation errors computed during ordinary model selection already show it: the shared model was worse on validation in 84–98\% of machine–fold–seed units, and validation and test ratios were rank-correlated in 12 of 14 settings. A gate that shares only within 1\% of the independent models' validation error therefore consolidated just 8–20\% of units, whereas letting validation choose which resources share a model kept 53\% of the LSTM's model reduction at a typical-cell cost of at most 0.4\%. In the shared LSTM, task gradients were close to orthogonal but strongly unequal in magnitude, and a loss-balancing intervention narrowed the cost only slightly. Prior comparisons of channel-independent and channel-dependent forecasting change input scope and sharing together; the design separates them. We believe the work fits FGCS's scope on distributed dynamic resource management, monitoring tools and cloud infrastructures, because it gives practitioners a tested way to decide input selection and model consolidation for multi-resource forecasting.

The six-block LSTM experiment, the four-backbone experiment and the two amendments (loss balancing, and validation-gated consolidation on the existing fits) were each frozen before execution, and later sensitivity controls are labelled post hoc throughout. The code is public at \url{https://github.com/KADOUMAAbdelhak/TimeTrack-Forecasting-Framework} at tagged commits, including fgcs-v04-a3-validation-gate-r2, and the derived analysis outputs are deposited on Zenodo (doi:10.5281/zenodo.24339239, doi:10.5281/zenodo.24353235 and doi:10.5281/zenodo.24458960); third-party traces remain available from their original archives. Generative AI use is disclosed in the manuscript as required by Elsevier's policy.

The manuscript states two limitations openly: on the 20 Bitbrains virtual machines no model beats persistence for CPU or throughput, even with a validation-selected persistence fallback, and the modern backbones use fixed, untuned settings. To address the first, we have prepared a follow-up analysis in which every model forecasts the change from the last observed value, so that each model contains persistence as a special case. Its protocol, code and decision rule were fixed under the public Git tag fgcs-v04-a2-residual before any of its fits, and we can report its results during review.
